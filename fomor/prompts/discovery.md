# 任务：生成 Discovery

把一次探索整理成用户可阅读、可判断的结果。不要写成资讯摘要，也不要把搜索结果直接堆给用户。

## 输入

主题：{{topic_name}}

近期事件：

{{events}}

问题理解：

{{understanding}}

机会评分：

{{score}}

方案探索：

{{exploration}}

## 输出要求

1. 标题以用户问题或新思路为中心，不以工具名为中心；
2. 说明「为什么是现在」：引用近期问题，但不要暴露过多原文；
3. 对目标与根本问题保持不确定性，不要写成定论；
4. 主方案讲清机制与流程，其他方案说明关系与适用条件；
5. 比较不是「A 比 B 好」，而是「在什么条件下选哪个」；
6. 证据只列真实存在的来源；没有就写 `unverified`；
7. 给用户留下反馈入口的语义（继续深入 / 已了解 / 不相关），但当前版本不实现按钮。

## 输出 JSON

```json
{
  "title": "string",
  "observed": "我观察到了什么",
  "problem_statement": "你真正可能在解决什么问题",
  "primary_solution_name": "必须来自输入方案",
  "comparison": "与当前方式的区别、代价与适用条件",
  "closing_question": "一个帮助用户判断的开放式问题",
  "evidence": ["string"],
  "confidence_notes": "哪些是推断，哪些还没确认"
}
```
