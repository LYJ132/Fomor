# Fomor 待确认问题清单

> 来源：[PRD V0.1](./PRD.md) 第十四、十五章及各章节中散落的未定稿事项。
> 配套调研：[Trae 平台能力调研](./TRAE-PLATFORM-RESEARCH.md)。
> 本文只负责「把问题问清楚」，不在缺乏依据时替产品下结论。

## 0. 使用说明

### 0.1 优先级定义

| 优先级 | 含义 | 处理要求 |
| --- | --- | --- |
| **P0** | 阻塞 MVP 立项或首个可运行闭环 | 进入开发前必须有结论 |
| **P1** | 影响 MVP 体验或效果，但不阻塞主链路 | MVP 开发期间给出方案 |
| **P2** | 影响后续版本或规模化 | 可延后，但需登记 |

### 0.2 状态定义

`待讨论` → `有倾向` → `已验证` → `已决策`（被否决的记为 `已否决`）

### 0.3 当前总体判断

真正卡住 MVP 的不是算法细节，而是三件事：

1. **采集链路能不能在 Trae 上稳定成立**（Hook 分发、安装、权限、会话上下文）。
2. **观察与假设的输出质量能不能被验证**（三个案例是否产生有启发的探索）。
3. **长期记忆能不能安全落地**（`~/.fomor/` 的写入权限、备份与迁移；隐式反馈如何准确归因）。

交付形态本身已收敛为「Trae 自动化任务输出」，不再是开放问题。

| --- | --- | --- | --- |
| E1 Hook 采集 | 验证 Trae Hook 能否稳定记录 prompt/session_id | 真实使用 1 天 | 事件无丢失、无重复、对 Agent 无可感知延迟 |
| E2 多工作区去重 | 验证全局 + 项目 Hook 合并时的重复问题 | 多项目工作区 | 同一消息只记录 1 条 |
| E3 会话上下文读取 | 验证 `session_id` 能否还原指代 | 「第二种方式」类追问 | 能定位前序消息；不能时明确返回未知 |
| E4 聚合评测 | 验证问题聚合质量 | 三个案例的真实问题集 | 人工标注对比，合并/拆分准确率达到预设阈值 |
| E5 根因假设 | 验证是否过度推断 | 同一批问题 | 每个假设都有原文证据；无证据时输出「不确定」 |
| E6 探索质量 | 验证方案是否有启发、可执行 | 三个案例 | 盲评中 ≥ 半数被认为「提供了新方向」且无事实错误 |
| E7 插件交付 | 验证插件安装、Skill 调用、`~/.fomor/` 读写 | 打包一个最小插件包 | 安装后可运行分析 Skill，结果写回数据目录 |
| E8 自动化任务 | 验证定时触发、运行环境、输出位置、执行历史 | 创建一个每日分析自动化任务 | 到点执行、输出可见、失败可补跑 |
| E9 目录权限与备份 | 验证 Hook 写入、`0700`、备份恢复、换机迁移 | 产生数据 → 备份 → 恢复；模拟迁移 home | 数据完整可恢复，权限正确 |
| E10 隐式反馈 | 验证次日回看能否正确归因 | 生成 Discovery → 次日提一个相关问题 → 再运行 | 正确 promoted；无关提问不误判 |
| E11 时间边界 | 验证漏跑、迟到、同日重跑 | 模拟漏跑 1/3/7 天、第 8 天追问、同日运行两次 | 不丢反馈、不重复升级、到期后才删除 |
| E12 03:00 睡眠 | 验证凌晨任务是否执行 | 电脑睡眠 → 03:00 任务 → 次日查看执行历史 | 明确「不执行/延迟补跑/系统唤醒可行」三者之一 |
